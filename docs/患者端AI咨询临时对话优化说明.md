# 患者端 AI 咨询临时对话优化说明

## 优化概述

将患者端 AI 咨询从**持久化存储**改为**临时对话**，对话数据仅保存在内存中，退出登录时自动清除，返回主页时保留对话。

---

## 核心改进

### 1. 不再存储到数据库

**之前的问题**：
- 患者端直接引用医护版 `ChatPage.vue`
- 使用 `consultationStore` 管理对话
- 每次对话都会创建 session 并保存到数据库
- 患者能看到医护人员的聊天记录（数据混乱）

**现在的实现**：
- ✅ 完全重写患者端 `ChatPage.vue`
- ✅ 使用组件内 `ref` 保存对话（内存中）
- ✅ 不调用后端 session API
- ✅ 不创建 `AiChatSession` 和 `AiChatMessage` 记录

---

### 2. 对话生命周期管理

#### 场景 1：返回主页 → **保留对话** ✅

```
AI咨询页面 → 点击"返回主页" → 主页 → 再次进入AI咨询
                                    ↓
                              对话仍然存在 ✓
```

**原因**：Vue Router 路由切换不会销毁组件实例，`messages` ref 保持不变。

#### 场景 2：退出登录 → **清除对话** ✅

```
AI咨询页面 → 点击"退出登录" → 登录页面
                                    ↓
                              ChatPage 组件被销毁
                              messages ref 被清空 ✓
```

**原因**：退出登录后跳转到 `/patient-login`，患者端路由守卫会卸载所有患者端组件，包括 ChatPage。

## 注意事项

### 1. 对话丢失风险

**场景**：用户刷新页面或关闭浏览器标签

**结果**：对话会被清除（因为保存在内存中）

**解决方案**（可选）：
- 如果需要持久化，可以使用 `localStorage` 临时保存
- 但根据需求，当前设计是**故意不持久化**的

### 2. 长对话性能

**场景**：用户进行非常长的对话（100+ 条消息）

**影响**：
- 内存占用增加
- 滚动可能变慢

**解决方案**（可选）：
- 限制最大消息数量（如 50 条）
- 超过限制时提示用户开启新对话

### 3. 并发请求处理

**实现**：使用 `requestGeneration` 计数器防止竞态条件

```typescript
let requestGeneration = 0

async function handleSend() {
    const currentGen = ++requestGeneration
    
    // ... 发送请求 ...
    
    if (currentGen !== requestGeneration) return  // 忽略旧请求
}
```
