# 修改诊断模块说明

## 📋 功能概述

"修改诊断"模块用于处理被审批退回(rejected)和需要修正(revision_needed)的AI患者报告。医生可以在此查看退回原因，修改报告内容后重新提交审批。

## 🎯 核心功能

### 1. 统计卡片
- **已退回**：显示被审批人退回的报告数量
- **需修正**：显示需要修正的报告数量
- **总计**：两者之和

### 2. 列表展示
显示所有待修改的报告，包含：
- 患者信息（姓名、编号）
- 主要发现（疾病名称 + 概率）
- 诊断编号
- 状态（已退回/需修正）
- 退回原因/修正意见
- 审批人
- 退回时间

### 3. 筛选功能
- 按关键词搜索（患者姓名/编号）
- 按状态筛选（全部/已退回/需修正）

### 4. 操作功能

#### 修改报告
点击"修改报告"按钮，打开对话框：
- 显示患者详细信息
- 显示退回原因或修正意见
- 显示AI原始报告内容
- 提供文本框编辑修改后的报告
- 填写修改说明
- 提交后自动将审批状态改为"已通过"

#### 重新生成
点击"重新生成"按钮：
- 调用LLM重新生成AI报告
- 创建新版本报告
- 适用于AI报告质量不佳的情况

## 🔧 技术实现

### 前端文件
- `frontend/src/views/revise/RevisePage.vue` - 主页面组件

### 后端API
- `GET /api/v1/approvals/` - 获取审批列表（支持status过滤）
- `GET /api/v1/approvals/:id` - 获取审批详情
- `GET /api/v1/approvals/stats` - 获取审批统计
- `PUT /api/v1/reports/:id` - 更新报告内容
- `POST /api/v1/reports/:id/regenerate` - 重新生成报告
- `POST /api/v1/approvals/:id/approve` - 通过审批

### 路由配置
```typescript
{
  path: '/staff/revise',
  name: 'Revise',
  component: () => import('@/views/revise/RevisePage.vue'),
  meta: { title: '修改诊断', icon: 'Edit' }
}
```

## 📊 工作流程

```
审批人退回/要求修正
    ↓
报告显示在"修改诊断"列表
    ↓
医生查看退回原因
    ↓
选择操作：
├─ 修改报告 → 编辑内容 → 提交 → 审批通过
└─ 重新生成 → AI重新生成 → 覆盖原报告
```

## 🎨 UI设计特点

1. **状态区分**：
   - 已退回：红色边框 + 红色状态标签
   - 需修正：橙色边框 + 橙色状态标签

2. **统计卡片**：可点击快速筛选对应状态

3. **修改对话框**：
   - 左右对比：AI原始报告 vs 修改后报告
   - 清晰展示退回原因
   - 必填项提示

## 💡 使用场景

### 场景1：报告内容有误
审批人发现AI生成的报告中某些描述不准确，选择"请求修改"并填写修正意见。医生在"修改诊断"页面看到该报告，手动修改错误内容后提交。

### 场景2：报告质量不佳
审批人认为AI报告整体质量不达标，选择"驳回"。医生可以选择"重新生成"让AI重新分析，或者手动重写报告。

### 场景3：补充临床信息
审批人指出报告缺少某些重要的临床关联分析。医生结合患者实际情况，补充相关信息后提交。

## ⚠️ 注意事项

1. 只有`doctor`和`admin`角色可以访问此模块
2. 修改报告后会自动将审批状态改为"已通过"
3. 重新生成会创建新版本报告，保留历史版本
4. 必须填写修改说明才能提交

## 🔄 与审批流程的关系

```
诊断完成 → 提交审批 → 审批人审核
                          ├─ 通过 → 报告归档
                          ├─ 驳回 → 修改诊断模块
                          └─ 请求修改 → 修改诊断模块
```

修改诊断模块是审批流程的重要补充，确保所有报告都能得到妥善处理。
